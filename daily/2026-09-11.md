## 一、3483：不同三位偶数的数目

题目要求从 `digits` 中选择三个数字组成三位偶数，要求：

- 百位不能为 0。
- 个位必须是偶数。
- 每个数组元素最多使用一次。
- 统计不同三位偶数的数量。

由于数字只可能是 `0~9`，可以先统计频次：

```cpp
vector<int> cnt(10, 0);
for (int x : digits) {
    cnt[x]++;
}
```

然后按“百位 -> 十位 -> 个位”枚举数字值，而不是枚举数组下标：

- 百位：`1~9`
- 十位：`0~9`
- 个位：`0,2,4,6,8`

选择某一位后，将对应频次减一，下一层只能使用剩余数字；离开这一层时再恢复频次。

典型结构：

```cpp
for (int a = 1; a <= 9; a++) {
    if (cnt[a] == 0) continue;
    cnt[a]--;

    for (int b = 0; b <= 9; b++) {
        if (cnt[b] == 0) continue;
        cnt[b]--;

        for (int c = 0; c <= 8; c += 2) {
            if (cnt[c] > 0) {
                // 当前三位数可构成
            }
        }

        cnt[b]++;
    }

    cnt[a]++;
}
```

核心思想是：

```text
选择 -> 修改状态 -> 继续选择 -> 恢复状态
```

这和之后学习回溯时常见的“做选择 / 撤销选择”非常相似。

由于只有 10 个数字值，枚举规模最多约为 `9×10×5`，加上统计频次后整体可看作 `O(n)`。

## 二、1475：商品折扣后的最终价格

最直接的做法是：对每个位置 `i`，向右寻找第一个满足：

```cpp
prices[j] <= prices[i]
```

的位置 `j`。

双循环最坏时间复杂度为 `O(n^2)`。

### 单调栈优化

从左到右遍历时，用栈保存“还没有找到折扣的商品下标”。

当当前价格 `prices[i]` 满足：

```cpp
prices[i] <= prices[st.top()]
```

说明当前商品就是栈顶商品右边第一个满足条件的折扣，因此可以立即结算并弹栈：

```cpp
while (!st.empty() && prices[i] <= prices[st.top()]) {
    int j = st.top();
    st.pop();
    ans[j] = prices[j] - prices[i];
}

st.push(i);
```

建议先：

```cpp
vector<int> ans = prices;
```

这样如果某个商品最终没有折扣，就不需要额外处理。

## 三、为什么单调栈是 O(n)

虽然代码中有 `for + while`，但不是 `O(n^2)`。

每个下标最多：

```text
入栈一次
出栈一次
```

因此总 `push` 次数不超过 `n`，总 `pop` 次数也不超过 `n`，总操作数量是线性的。

这种分析方式叫摊还分析。

## 四、单调栈适用信号

看到下面关键词时，应考虑单调栈：

```text
左边 / 右边
第一个 / 最近的
更大 / 更小
```

典型问题：

- 右边第一个更小。
- 右边第一个更大。
- 左边第一个更小。
- 左边第一个更大。

常见经验：

```text
找更小 -> 常维护递增栈
找更大 -> 常维护递减栈
```

具体方向仍要结合遍历顺序和题目条件判断。

## 五、今日核心收获

1. 当值域很小且固定时，可以优先考虑频次数组，而不是枚举所有下标组合。
2. `cnt[x]--` 与 `cnt[x]++` 是一种典型的“修改状态 / 恢复状态”模式。
3. 单调栈适合解决“左/右边第一个更大或更小”这类问题。
4. 单调栈中常存下标而不是值，因为后续通常需要修改对应答案位置。
5. `for + while` 不一定是 `O(n^2)`；如果每个元素只入栈、出栈一次，整体仍是 `O(n)`。
6. LeetCode 单次显示的 0ms、3ms 等存在波动，判断优化效果应优先看复杂度，而不是一次运行时间。
