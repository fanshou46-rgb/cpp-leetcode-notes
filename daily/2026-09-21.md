## 一、循环队列的推荐写法

使用：

```cpp
vector<int> q;
int front;
int count;
int capacity;
```

只维护队首和元素数量，队尾位置通过公式计算。

下一个插入位置：

```cpp
(front + count) % capacity
```

当前队尾位置：

```cpp
(front + count - 1) % capacity
```

出队：

```cpp
front = (front + 1) % capacity;
count--;
```

判空与判满：

```cpp
count == 0
count == capacity
```

相比同时维护 `front + back + count`，这版状态更少，更不容易漏更新。

## 二、构造函数里的成员变量问题

错误写法：

```cpp
MyCircularQueue(int k) {
    vector<int> a(k);
    int sum = k;
    int have = 0;
}
```

这些是局部变量，构造函数结束后就不存在。

正确做法：先把变量定义成类成员，再在构造函数中初始化。

## 三、1705 的空堆错误

错误：

```cpp
while (i >= q.top().first && !q.empty())
```

C++ 的 `&&` 从左向右计算，因此会先执行：

```cpp
q.top()
```

如果堆为空就产生未定义行为。

正确：

```cpp
while (!q.empty() && i >= q.top().first)
```

先确认容器非空，再访问堆顶。

同类写法：

```cpp
i < nums.size() && nums[i] == x
```

核心原则：

> 先判断“能不能访问”，再执行访问操作。

## 四、链表底层结构

链表不是连续数组，而是由节点通过指针串起来：

~~~cpp
struct ListNode {
    int val;
    ListNode* next;
};
~~~

遍历的本质：

~~~cpp
for (ListNode* cur = head; cur != nullptr; cur = cur->next) {
    // 使用 cur->val
}
~~~

核心区别：

- 数组随机访问 O(1)，链表随机访问 O(n)。
- 已知节点位置时，链表插入/删除只改指针，可为 O(1)。
- 修改 next 前要先保存后继，避免把后半段链表弄丢。
- 处理头节点删除/插入时，dummy 虚拟头节点很有用。

## 五、stringstream 日期解析

需要：

~~~cpp
#include <sstream>
~~~

例如：

~~~cpp
string date = "2026-09-21";
stringstream ss(date);

int y, m, d;
char c1, c2;

ss >> y >> c1 >> m >> c2 >> d;
~~~

stringstream 可以把 string 当成输入流，按预期格式依次读出整数和分隔符。

如果只是固定格式日期，比手动多次 find + substr 更直接。

详细专题：[字符串基础](../knowledge/string-basics.md)

## 今日核心收获

1. 循环队列可以只维护 `front + count`。
2. `back` 如果表示“下一次插入位置”，就不是当前队尾。
3. 容器的 `top/front/back` 在空容器上不能调用。
4. `&&` 有短路特性，安全条件应放在左边。\n5. 链表通过 next 指针连接节点，遍历必须从头逐个向后。\n6. 修改链表指针时要先保护后继节点，避免断链。\n7. `stringstream` 适合解析日期等“固定格式字符串”。
